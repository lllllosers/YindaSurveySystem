# Yinda Survey Web Center

`web_center/` 是“引大调查数据采集系统 / YindaSurveySystem”的 Web 业务中心。

当前阶段是 **V1.2.0 中心管理平台**。Web 中心与稳定桌面端使用同一套 `.ydtask V3 / .ydresult 2.2` 业务协议：中央人员在浏览器中管理项目、批次、任务、成果审核和正式成果库，桌面端继续承担离线调查填报。

## Web 与桌面端协同方式

Web 端不是桌面端的重复版本，两端各自承担最适合的工作：

```text
中心建立项目与批次
  ↓
Web 下发任务文件
  ↓
基层桌面端接收任务并离线调查 ─┐
                               ├→ 中心统一审核 → 正式成果库
Web 在线补录与内业填报 ────────┘
  ↓
统一查询、统计和审计
```

这套协同方式带来的直接改善：

- 项目、批次、调查单位和范围只在中心统一确定，桌面端随任务自动带入，减少重复填写；
- 基层现场不依赖网络，继续使用已经稳定的桌面端录入表格和影像；
- 成果上传后自动检查文件完整性、任务范围和数据版本，减少人工逐包核对；
- 多单位成果集中入库，省去反复合并表格、查找最新文件和核对责任单位；
- Web 在线补录和桌面离线调查使用同一任务、同一基础资料和同一正式成果库，不形成两套账；
- 任务、审核、退回和入库均可追溯，便于后续查询、统计和责任确认。

首页主视觉采用原创的庄浪河大渡槽主题图片，用于产品界面展示，不作为工程档案照片或现场影像使用。

## 一键启动（推荐）

在仓库根目录双击：

```text
启动Web管理中心.bat
```

会打开深色服务控制台，并自动完成：

- 检查 PostgreSQL、后端环境、前端依赖和本地配置；
- 执行 Alembic 数据库迁移；
- 启动业务后台和网页服务；
- 持续显示三个服务的在线状态与运行日志；
- 服务就绪后自动打开浏览器；
- 支持一键打开业务页面、查看服务状态，以及停止本次启动的服务；
- 自动识别旧版后台，避免前端已更新但后台仍为旧版时出现页面不可用。

如果已有服务占用端口，控制台会识别并复用，不会把外部启动的进程当作自己的进程关闭。

访问地址：

```text
Web:      http://127.0.0.1:8848
API Docs: http://127.0.0.1:8000/docs
```

使用已有管理员账户登录。如果忘记本机 Web 管理员密码，可关闭服务后双击根目录的 `重置Web管理员密码.bat`，按提示输入管理员用户名和新密码；输入过程不会显示密码字符，也不会把明文写入文件。

## 架构边界

### Web 中心负责

- 项目与调查批次管理；
- 用户、角色与权限；
- 操作审计；
- 管理处、管理所、渠系和分管范围新增、修改、停用、启用及安全删除；
- 基础资料中央版本管理，新任务自动携带当时版本的冻结快照；
- 面向管理处或水管所创建调查任务并生成桌面端兼容 `.ydtask V3`；
- 批量登记桌面端已经下发的原始 `.ydtask`，无损接续投产中的历史任务；
- `.ydresult 2.2` 成果包安全接收、SHA-256 留存和文件归档；
- 按 Web 实际下发任务的冻结范围执行来源、组织、渠系、表单和版本冲突预检；
- 成果审核接收/退回、入库前复检和事务化正式入库；
- 附表 2.1～2.14 Web 在线录入、草稿、提交、退回修改、审核和正式入库；
- Web 在线录入照片、视频上传及桌面成果影像统一查看；
- Web 与桌面成果双向查重，避免同一调查对象形成两条正式记录；
- 中央成果库查询、详情、单位分布汇总和 CSV 导出。

### PySide6 桌面端继续负责

- 离线调查填报；
- 附表 2.1～2.14 业务表单；
- 本地 SQLite；
- 照片、视频等调查影像；
- 草稿和 completed 调查记录维护；
- 正式原表导出；
- `.ydtask` / `.ydresult` 本地包生成与使用。

Web 中心不直接共享或同步桌面端 SQLite。
中央 PostgreSQL 正式成果库是唯一事实源；桌面 SQLite 是离线工作区，任务包和成果包是受控交换载体。

## 当前验收范围

- 现代化登录页与中央工作台；
- 登录页和工作台采用原创庄浪河大渡槽主题主视觉；
- 导航、状态、操作提示和异常提示均使用面向业务人员的中文表达，不直接展示内部技术编号；
- 服务、数据库和业务统计概览；
- 项目和调查批次管理；
- 正式基础资料维护：5 个管理处、20 个管理所、68 条渠道、63 条管理范围，并支持后续业务调整；
- 渠道按干渠、分干渠、支渠、分支渠维护层级，支持按桩号分段分所管理；
- 面向管理处/水管所生成、下载、取消调查任务；
- 附表 2.1～2.14 在线录入、提交审核、退回修改和正式入库；
- 任务冻结范围、表单版本和任务谱系留存；
- 用户与角色权限管理；
- `.ydresult` 上传、结构检查、业务预检、审核、归档、完整性复检与正式入库；
- 正式成果库筛选、详情、来源追溯、单位分布和 CSV 导出；
- 审计日志。

首次启用时，系统以 `shared/master_data/official_master_contract.json` 初始化中央基础资料库；此后以 PostgreSQL 中央版本为正式依据。自动测试会检查初始基线与桌面端 V1.2 常量一致。

## `.ydresult` 协议说明

上传阶段先用独立只读检查器执行 ZIP、manifest、文件清单和哈希安全检查；业务预检及正式入库阶段直接调用桌面端 V1.2 的 `survey_result_package_reader`。因此正式协议规则仍以稳定桌面端实现为事实源，Web 不维护第二套业务协议。

Web 入库不会用当前主数据覆盖历史事实。每条正式记录继续保留 `source_task_uid + source_management_scope_uid`；本次向中心提交所依据的任务使用 `submission_task_uid`。处级汇总包可以保留下级真实任务来源，中心按自己下发的处级父任务冻结范围验收。

## 权限边界

当前仅保留已经真实实现的权限：

- `admin`：全部权限；
- `manager`：项目、批次、基础资料、任务下发、在线录入与审核、成果上传/预检/审核/入库、正式成果库和审计；
- `reviewer`：项目、批次、任务读取/下载、成果预检/审核和正式成果库；
- `viewer`：项目、批次、任务、成果与正式成果库只读。

## 安全和部署边界

当前默认配置面向本机 HTTP 开发：

```text
SESSION_COOKIE_SECURE=false
```

正式 HTTPS 部署必须改为：

```text
SESSION_COOKIE_SECURE=true
```

PostgreSQL 不应直接暴露公网。

当前成果文件使用服务器本地文件系统：

```text
web_center/backend/storage/
```

该目录不进入 Git。

当前本地验收版不引入 Redis、Celery、对象存储或微服务。现有正式主数据没有工程坐标，因此页面提供真实的单位/渠道成果分布汇总，不绘制没有数据依据的伪 GIS 地图；后续取得坐标数据后可在中央成果库模型之上增加地图视图。

业务协同细则见 `docs/14_Web与桌面端数据协同规则.md`，本阶段人工验收步骤见 `docs/16_Web基础资料与录入验收说明.md`。
