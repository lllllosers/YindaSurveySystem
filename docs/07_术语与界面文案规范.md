# YindaSurveySystem 术语与界面文案规范

本规范用于桌面端、后续 Web 端、用户手册和测试用例中的用户可见业务文案。目标是统一业务口径，不改变数据库字段、Python API、内部枚举、文件格式或既有数据协议。

## 1. 当前上下文

- 当前项目：当前正在开展调查工作的项目。
- 当前调查批次：当前项目下正在使用的调查批次。
- 左侧模块名称统一使用“项目/批次”。
- 用户界面不再使用“当前批次”“本批次”指代当前调查批次。

## 2. 任务流程

- 一级分组：任务管理。
- 二级入口：任务分发、任务接收。
- “任务分发”指生成并交付调查任务包。
- “任务接收”指执行端选择并接收调查任务包。
- 文件名称统一称为“调查任务包（.ydtask）”。
- 具体动作优先使用“生成任务包”“选择并接收任务包”“检查任务包”。
- 内部历史事实、数据库服务或审计语境中的“已下发任务”可以保留，不机械改写。

## 3. 成果流程

- 一级分组：成果管理。
- 二级入口：成果提交、成果接收。
- “成果提交”是业务模块名称。
- 模块内具体文件操作仍可使用“导出正式成果”“生成调查成果包”等明确动作。
- “成果接收”是业务模块名称；具体动作使用“检查成果包”“正式导入成果”等。
- 文件名称统一称为“调查成果包（.ydresult）”。
- “查询结果”仅表示数据查询模块产生的结果集，不与“调查成果”混用。

## 4. 调查记录状态

- 草稿：记录已保存但尚未完成调查。
- 录入完成：记录已经通过完成校验，可进入正式成果。
- 用户界面的记录状态标签和记录数量统计统一使用“草稿 / 录入完成”。
- “完成调查”保留为操作名称；自然语句中的“已完成调查记录”可以保留。
- `draft`、`completed` 等内部状态值不改名。

## 5. 工程调查对象

- 工程台账：长期工程对象集合，可跨调查批次存在。
- 工程详情：长期工程对象的基本信息及历次调查。
- 调查记录：某一工程在某一调查批次形成的一次调查数据。
- 调查表：用户填写或查看的业务表单。
- 正式原表：按甲方正式模板输出的单条 Excel 调查表。
- 详细汇总：按调查表汇总的明细 Excel。

## 6. 组织与渠系

- 基层处：组织机构第一层级。
- 管理单位：承担具体调查或渠道管理职责的末级管理单位；具体正式名称仍按主数据展示。
- 渠道：物理渠道实体。
- 渠系：渠道的层级体系或所属层级语境。
- 分管范围：管理单位对某条物理渠道的全渠或分段管理范围。
- “渠道”“渠系”“分管范围”分别代表不同业务概念，不做机械互换。

## 7. 文案使用原则

1. 页面标题、导航名称、按钮、筛选项、状态标签和弹窗提示优先使用本规范术语。
2. 技术扩展名 `.ydtask`、`.ydresult` 作为辅助说明，不作为主要按钮名称。
3. 不为统一用户文案而修改数据库列名、JSON key、类名、函数名、变量名、协议字段或历史数据。
4. CHANGELOG 中已经发生的历史描述原则上保留；当前 README、页面说明和用户手册使用现行口径。
5. 正式调查原表中的评价标准和甲方原始业务文字不因本规范擅自改写。

## 8. 第二批界面语义细则

- 基础资料中的单个 CanalUnit 统一称为“渠道”；“渠系”用于渠道层级体系、所属层级和跨渠道结构语境。
- 渠道实体与管理单位之间的业务关系统一称为“分管范围”；“管理分管段”保留为渠道基础资料页的操作按钮名称。
- 首页统计指标统一称为“已录记录完成率”，定义为：录入完成记录数 ÷ 已录记录数。该指标不代表辖区最终工作量完成率。
- 任务和成果页面的主操作使用业务动作名称；`.ydtask`、`.ydresult` 作为文件格式辅助说明，不直接作为主要按钮名称。
- 调查成果包中的正式记录状态表述使用“录入完成”，与界面记录状态保持一致。
- 已经完成的业务能力不得继续显示“下一阶段接入”等开发阶段占位说明。

## 9. 面向业务人员的文案原则

- 页面、按钮、状态栏和弹窗优先回答三个问题：**现在是什么状态、用户要不要处理、下一步做什么**。
- “预检”统一改为“检查”；“工作区”统一表达为“当前任务”。
- `UID`、内部错误代码、`revision`、`package_uid`、`result_uid`、任务谱系字段等内部技术代码不直接展示给业务人员。
- “数据库事务”“回滚”“托管文件”“Registry”“CanalManagementScope”等开发实现术语不作为用户说明。
- 只有**需要用户采取行动**的问题才使用“需处理”“失败”“不可继续”等表达。
- 已经由任务下发记录成功核验、且不影响导入的历史范围变化，使用“说明”，不再显示为“警告”。
- 文件扩展名 `.ydtask`、`.ydresult` 可以在文件选择器或辅助说明中保留，但主按钮继续使用“任务包”“成果包”等业务名称。
- 内部技术诊断信息继续保留在服务对象、日志和自动化测试中，界面展示使用单独的业务人员版本。
