## Engineering Form Framework

附表2.1～2.6的工程调查录入层已经完成统一重构。

核心结构：

```text
FORM_2_X
    ↓
EngineeringFormRegistry
    ↓
GenericEngineeringSurveyPage
    ↓
forms.engineering.persistence
    ↓
point / range common DB API
```

当前正式代码级表单身份来源为：

- `src/forms/engineering/form_2_1.py`
- `src/forms/engineering/form_2_2.py`
- `src/forms/engineering/form_2_3.py`
- `src/forms/engineering/form_2_4.py`
- `src/forms/engineering/form_2_5.py`
- `src/forms/engineering/form_2_6.py`
- `src/forms/engineering/registry.py`

工程类型代码、字段定义、位置类型、评价配置等表级事实应优先由 `EngineeringFormDefinition` 提供。

## 当前架构原则

- 本次调查负责当前批次录入管理
- 数据查询负责跨批次、跨表查询、统计和汇总导出
- completed记录允许继续修改，但必须保持完整
- 工程身份建立后保持稳定
- 相同业务语义必须优先复用同一实现
- 表单自身不同的业务内容通过定义或受控扩展表达
- 避免重新出现逐表复制完整CRUD、完成逻辑和录入页面
- 不为了减少文件数量而强行合并真实存在的业务差异
- 附表1与附表2按各自数据模型分别设计，不强行共用同一调查框架

