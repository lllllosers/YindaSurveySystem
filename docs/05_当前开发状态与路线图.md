## Engineering Form Framework

附表2.1～2.14统一使用以下结构：

```text
EngineeringFormDefinition
├── core identity / fields / position / evaluation
├── ListDefinition
├── SummaryExportDefinition
└── OriginalFormExportDefinition
        │
        ↓
EngineeringFormRegistry
        │
        ├── GenericEngineeringSurveyPage
        │       ↓
        │   forms.engineering.persistence
        │       ↓
        │   point / range common DB API
        │
        ├── GenericEngineeringListPage
        │       ↓
        │   EngineeringSurveyListPage
        │
        ├── engineering_summary_export
        └── engineering_original_form_export
```

生产代码中的工程调查表身份统一从 `EngineeringFormRegistry` 获取。

表级正式事实主要位于：

- `src/forms/engineering/form_2_1.py` ～ `form_2_14.py`

## 当前架构原则

- EngineeringFormDefinition表达表级事实，执行逻辑不塞入Definition
- EngineeringFormRegistry作为生产层已接入工程表单的统一入口
- 当前批次列表与跨批次数据查询职责分离
- completed记录允许继续修改，但必须保持完整
- 工程身份建立后保持稳定
- 相同业务语义优先复用同一实现
- 真实业务差异通过表级Definition、纯formatter或受控扩展表达
- 不建立JSON/YAML驱动的通用低代码表单平台
- 不为了减少文件数量而合并仍有清晰职责边界的模块
- 附表1与附表2按各自数据模型分别设计
