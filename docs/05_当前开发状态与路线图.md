        ↓

## 当前架构原则

- EngineeringFormDefinition表达表级事实，执行逻辑不塞入Definition
- EngineeringFormRegistry作为生产层已接入工程表单的统一入口
- 当前批次列表与跨批次数据查询职责分离
- completed记录允许继续修改，但必须保持完整
- 工程身份建立后保持稳定
- 相同业务语义优先复用同一实现
- 真实业务差异通过表级Definition、纯formatter或受控扩展表达
- 不建立JSON/YAML驱动的通用低代码表单平台
- 不为了减少文件数量而合并仍有清晰职责边界的模块
- 附表1与附表2按各自数据模型分别设计

## 后续工程调查表接入原则

标准附表2.x不应再新增：

- 专属录入页面
- 专属 CRUD / completion service
- 专属当前批次 List Page
- 复制版 summary exporter
- 复制版 original-form exporter

标准接入内容应集中为：

1. FORM_2_X定义；
2. 正式评价项目；
3. List / Summary / Original Form声明；
4. 正式Excel模板；
5. 合同测试和workflow测试。

如果新表出现现有框架不能自然表达的真实差异，先确认该差异是否稳定、是否值得公共化，再增加最小扩展点。
