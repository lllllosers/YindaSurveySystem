# V1.2.0 发布说明

## 版本信息

- 产品名称：引大入秦工程现状调查采集系统
- 版本：V1.2.0
- 阶段：正式版
- 发布日期：2026-09-23
- 升级基线：V1.1.1

## 版本定位

V1.2.0 是 V1.1.1 的数据兼容升级版本。

本版本根据现场调查口径统一附表2工程位置表达：附表2.1～2.14全部采用“起始桩号 + 终止桩号”的区间语义。原本已经是区间工程的附表2.1、2.5、2.7保持不变；原本使用单桩号的附表2.2、2.3、2.4、2.6、2.8、2.9、2.10、2.11、2.12、2.13、2.14升级为起止桩号。

本版本不改变既有三级任务架构，也不提升 `.ydtask` / `.ydresult` 文件协议版本。

## 主要变更

### 1. 附表2.1～2.14统一起止桩号

11张原单桩号调查表现统一录入：

- 起始桩号；
- 终止桩号。

新建记录在“录入完成”前必须同时填写起始桩号和终止桩号。

对于原始 Excel 模板中表头仍为“桩号”的调查表，不修改原模板结构和表头，正式原表与详细汇总中的同一桩号单元格写入：

```text
起始桩号～终止桩号
```

本次不为原表中没有“长度”字段的工程类型额外增加长度字段。

### 2. V1.1.1 历史单桩号数据兼容迁移

V1.2.0 首次打开既有 V1.1.1 数据库时，对11张原单桩号附表执行兼容迁移：

```text
旧单桩号 -> 起始桩号
终止桩号 -> 留空，待现场或内业补充
```

迁移保留原 `single_stake_*` 和历史 `record_data.stake`，不猜测终止桩号。

兼容迁移不属于用户业务编辑，因此不会因为本次迁移主动增加：

- SurveyRecord revision；
- EngineeringAsset revision；
- source_revision；
- 业务记录 updated_at。

历史业务编号和稳定 UID 保持不变。

### 3. 历史 completed 状态保持

V1.1.1 中已经“录入完成”的旧单桩号记录升级后仍保持 completed，不因终止桩号为空被自动降级为草稿。

这些记录会在数据查询和工程台账中提示需要补充终止桩号。

当用户后续主动编辑此类历史 completed 记录时，需要补齐起始桩号和终止桩号后才能继续按 completed 状态保存。

### 4. 表单版本兼容

附表2.1～2.14均保留 V1 历史版本，同时建立 V2 作为当前版本。

规则如下：

- 历史调查记录继续绑定原 V1 `form_version_id`；
- 不批量改写历史记录的表单版本；
- 新建调查和新下发任务使用当前 V2；
- V1 保留用于历史任务、历史成果和历史记录兼容读取。

### 5. 旧成果包兼容

成果接收继续兼容旧单桩号成果数据。

当旧成果只有 `single_stake` / `record_data.stake` 时，导入过程只补充起始桩号，不自动生成终止桩号。

`.ydtask` 继续使用 V3，`.ydresult` 继续使用 2.2；本版本没有因为起止桩号升级而人为提升包协议版本。

### 6. 升级前自动安全备份

V1.2.0 对既有数据库执行首次升级前，会在任何数据库迁移发生之前自动创建 SQLite 安全备份。

备份文件保存在：

```text
local_data/backups/
```

文件名包含：

```text
pre_v1_2_0_upgrade
```

只有整个应用数据库初始化成功后才记录本次 V1.2.0 升级已完成。若初始化中途失败，下次启动仍会重新执行升级前保护。

全新安装没有旧数据库时不会创建无意义的空升级备份。

## 查询与台账提示

数据查询和工程台账对缺少起始桩号或终止桩号的记录进行醒目标识，用于甲方逐步补齐历史工程位置。

本版本不增加“桩号完整性”筛选条件，避免改变既有查询习惯。

## 正式交付包

V1.2.0 正式构建同时生成两套交付物：

```text
YindaSurveySystem_V1.2.0_Windows_x64.zip
YindaSurveySystem_V1.1.1_to_V1.2.0_Update.zip
```

第一套是完整发布包，用于全新安装、重装或没有既有 V1.1.1 安装目录的电脑。

第二套是甲方已有 V1.1.1 正式系统的专用安全升级包。该升级包不是源码级差分补丁，而是“完整 V1.2.0 payload + 安全升级程序”的覆盖式更新包，避免 PyInstaller `_internal` 等内部文件漏覆盖或新旧版本混用。

升级程序会：

1. 校验升级 payload SHA-256；
2. 确认目标目录确实为 V1.1.1；
3. 检查 `YindaSurveySystem.exe` 已完全关闭；
4. 在替换程序文件前复制完整 `local_data` 到 `upgrade_backups`；
5. 替换完整程序 payload，但不删除、不覆盖 `local_data`；
6. 若程序文件替换失败，自动回滚已替换的程序文件；
7. 更新成功后，首次启动 V1.2.0 再执行数据库级 `pre_v1_2_0_upgrade` 备份和兼容迁移。

因此正式甲方升级优先使用 `YindaSurveySystem_V1.1.1_to_V1.2.0_Update.zip`，而不是人工解压完整包覆盖。

## 升级说明

V1.2.0 可以在保留原 V1.1.1 `local_data` 的情况下直接替换程序升级。

建议的正式升级流程：

1. 完全关闭旧版程序；
2. 仍建议人工额外复制一份完整 `local_data` 作为外部保险；
3. 替换为 V1.2.0 程序；
4. 首次启动由程序自动创建 `pre_v1_2_0_upgrade` 数据库备份并执行兼容迁移；
5. 在工程台账和数据查询中逐步补充历史记录的终止桩号。

不要删除历史 V1 表单版本或手工批量重写历史 `form_version_id`。
