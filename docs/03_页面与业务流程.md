# 引大灌区调查数据采集系统
## V0.1 页面与业务流程设计

> 文档版本：V0.1  
> 当前阶段：页面与业务流程设计  
> 适用范围：V0.1 Demo  
> 原则：围绕单机、单用户、纸质调查后内业录入的实际流程设计，不提前实现尚未确认的复杂功能

---

## 1. 设计目标

V0.1 页面设计重点不是追求复杂视觉效果，而是确保以下业务闭环顺畅：

1. 能明确当前正在操作哪个调查项目和调查批次；
2. 能逐步建立基层处、水管所和渠系基础信息；
3. 能在第一次调查时边录入边建立工程对象台账；
4. 能完成附表 2.1 和附表 2.2 的规范化录入；
5. 能自动生成并校验业务编号；
6. 能保存、修改和查询调查记录；
7. 能查看工程对象及其历次调查记录；
8. 能按汇总表形式导出 Excel；
9. 能备份当前项目数据库；
10. 为后续附表 1、剩余附表 2、照片、坐标、综合判级等功能预留入口。

# 12. 新增工程调查总体流程

第一次调查没有完整工程底册，因此“新增工程调查”需要同时完成：

```text
确认/创建工程对象
+
创建本批次调查记录
```

总体流程：

```text
点击新增
    ↓
选择组织和渠系
    ↓
生成业务编号
    ↓
填写工程身份及基础信息
    ↓
创建工程对象
    ↓
填写本次调查内容
    ↓
保存草稿 / 完成录入
```

对用户而言不需要分成两个复杂页面。

UI 上可以表现为一个连续表单。

后台再分别保存 EngineeringAsset 和 SurveyRecord。

# 15. 编号生成逻辑

当前业务编号：

```text
基层处代码
-
水管所代码
-
渠道层级代码
-
工程类型代码
-
顺序号
```

系统行为：

```text
选择基层处
    ↓
只显示该处下属水管所
    ↓
选择水管所
    ↓
选择渠系
    ↓
识别渠道层级
    ↓
根据调查表识别工程类型
    ↓
自动建议下一个顺序号
    ↓
实时生成业务编号
```

# 17. 桩号输入

用户输入：

```text
K12+350
```

系统保存：

```text
显示值：K12+350
标准值：12350
```

允许常见输入形式：

```text
K12+350
12+350
12350
```

系统统一转换后保存。

若无法解析：

```text
提示用户检查格式
```

渠道类附表 2.1 使用：

```text
起始桩号
终止桩号
```

并可计算：

```text
渠段长度参考值 = 终止桩号 - 起始桩号
```

但 V0.1 不强制用计算值覆盖人工填写的渠段长度。

# 19. 评价项目交互

每一个评价项目显示：

1. 检查项目名称；
2. 等级选择按钮；
3. 对应等级标准；
4. 情况描述输入框。

例如用户点击：

```text
C
```

系统立即显示：

```text
C级标准：
闸室进、出口流态不稳，出现连续非贯穿性漩涡。
```

用户再填写现场事实：

```text
现场情况描述：
出口左侧存在明显回流，持续观察可见非贯穿性漩涡。
```

---

## 19.1 标准与描述分离

系统不得自动将：

```text
C级标准文字
```

直接作为：

```text
现场情况描述
```

标准用于判断参考。

现场描述必须由调查人员根据纸质调查记录录入。

---

## 19.2 未评价状态

每个检查项目默认状态：

```text
未评价
```

即：

```text
A / B / C / D / 未评价
```

附表仅包含 A/B/C 的项目则只显示对应等级。

## 21.1 保存草稿

点击：

```text

```

- 未填写字段；
- 未评价项目；
- 最终等级未确定。

用于中途录入和后续继续编辑。

---

## 21.2 标记完成

点击：

```text
标记完成
```

V0.1 应进行基础完整性检查。

至少检查：

- 是否存在业务编号；
- 工程名称是否为空；
- 所属机构是否完整；
- 是否存在明显非法数值；
- 必填字段是否填写。

对于当前尚未确定的评价业务规则：

```text
不强制最终等级必须填写
```

若存在未评价项目，可先给出提示，但是否阻止完成由后续实际使用反馈确定。

V0.1 建议：

```text
提示，但允许继续完成
```

# 22. 自动保存

考虑到调查表较长，系统应具备自动保存能力。

V0.1 建议采用：

```text
用户已经首次手动保存生成记录后
    ↓
后续字段修改定时自动保存
```

例如：

```text
每 30 秒检查一次是否发生修改
```

若有变化则保存。

顶部显示：

```text
已自动保存：10:35:42
```

对于尚未首次创建的全新记录：

```text
先由用户点击一次“保存草稿”
```

再进入自动保存流程。

这样可以避免一打开新表就产生大量空白记录。

# 24. 删除规则

V0.1 不提供随意删除正式历史调查数据。

建议：

### 草稿记录

允许删除，但需要二次确认：

```text
确定删除这条草稿记录？
```

### 已完成记录

暂不提供直接删除按钮。

后续根据实际管理要求决定：

- 作废；
- 恢复草稿；
- 管理员删除。

V0.1 单用户系统暂不开发权限体系。

# 35. 工程改造后的处理原则

```text
原则上仍作为同一个 EngineeringAsset
```

并在新调查批次中记录新状态。

如果未来出现：

```text
彻底拆除重建
工程身份发生实质变化
```

# 37. V0.1 基础数据校验

V0.1 先实现低争议规则：

- 业务编号不得重复；
- 数值字段不得输入非数值内容；
- 明显不允许为负的数值不得小于 0；
- 起始桩号不得大于终止桩号；
- 必填字段完成时必须填写；
- 已停用机构或渠系不作为新增记录默认选项。

暂不实现尚未确定的复杂业务校验。

# 39. UI 设计原则

V0.1 UI 遵循：

1. 录入效率优先；
2. 重要字段尽量不隐藏；
3. 不照搬 Word 表格排版；
4. 长评价标准按需显示；
5. 下拉选择优先于重复手工输入；
6. 关联字段自动联动；
7. 数值字段使用数值输入控件；
8. 日期字段使用日期控件或规范输入；
9. 不使用大量弹窗完成主要录入；
10. 软件在 1920×1080 常见 Windows 屏幕下应正常使用；
11. 优先支持鼠标和键盘连续录入；
12. 后续根据内业人员实际反馈调整。
