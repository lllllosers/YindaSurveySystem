# 引大灌区调查数据采集系统
## 04_附表2.1与2.2数据字典

> 文档版本：V0.1  
> 当前阶段：V0.1 Demo 数据字典  
> 数据来源：甲方最终定稿的附表2.1、附表2.2  
> 说明：本文件用于把纸质调查表转换为程序可识别的字段、控件、存储结构和评价项目配置。  
> 原则：源表内容不擅自增删；为了软件录入、查询和导出，可对个别复合字段进行结构化拆分，但导出时应能重新组合成甲方原表表达。

---

# 1. 本数据字典的作用

V0.1 Demo 首先实现：

- 附表2.1 防渗衬砌渠道渠段工程状况调查表；
- 附表2.2 水闸（进水闸、节制闸、分水闸、泄洪闸、退水闸）工程状况调查表。

本数据字典将用于后续：

```text
表单配置 JSON
↓
PySide6 动态录入界面
↓
SQLite SurveyRecord.record_data_json
↓
InspectionResult
↓
Excel 汇总导出
```

# 2. 字段设计约定

## 2.1 字段代码

程序内部字段使用英文 snake_case。

例如：

```text
设计流量      design_flow
建成年月      build_date
加固改造年月  renovation_date
```

中文名称只用于：

- UI；
- Excel；
- 帮助说明；
- 表单配置展示。

---

## 2.2 数据类型

当前使用以下基础数据类型：

```text
text        文本
integer     整数
decimal     小数
month       年-月
date        日期
stake       桩号
enum        枚举/下拉选择
```

---

## 2.3 控件类型

当前使用：

```text
line_edit       单行文本框
text_edit       多行文本框
spin_box        整数输入
double_spin     小数输入
month_edit      年月输入
date_edit       日期输入
stake_edit      桩号输入
combo_box       下拉选择
grade_selector  等级选择
```

---

## 2.4 必填说明

甲方源表目前没有明确标注每个字段的“必填/非必填”规则。

因此本数据字典不把源表字段擅自定义为正式业务必填项。

V0.1 软件只设置少量“系统最低必需字段”，用于保证记录能正确建立：

- 所属基层处；
- 所属水管所；
- 所属渠系；
- 业务编号；
- 工程/渠段名称。

其他字段在草稿状态均允许为空。

后续“录入完成”时的必填规则根据实际使用反馈再调整。

# 3. 公共头部字段

附表2.1和附表2.2表头均包含：

```text
处
所
干渠
支渠
编号
```

这些信息不作为普通 record_data_json 字段重复存储，而优先映射到系统核心关系字段。

| 源表字段 | 程序映射 | 说明 |
|---|---|---|
| 处 | organization_unit_id | 选择基层处 |
| 所 | organization_unit_id 对应下级水管所 | 选择水管所 |
| 干渠/支渠 | canal_unit_id | 选择具体渠系，由渠系自动判断层级 |
| 编号 | business_code | 系统自动生成业务编号 |

业务编号与数据库内部 ID 分离。

# 17. V0.1 基础校验规则

当前只实现低争议规则。

## 17.1 公共规则

- 业务编号不得重复；
- 所属基层处不能为空；
- 所属水管所不能为空；
- 所属渠系不能为空；
- 工程/渠段名称不能为空；
- 数值型控件不得接受非数值字符；
- 明显不应为负的长度、宽度、厚度、流量等不得小于0；
- 等级只能使用当前评价项目允许的等级。

---

## 17.2 附表2.1

- 起始桩号和终止桩号均可解析时，终止桩号不得小于起始桩号；
- 可显示“桩号差计算长度”供用户参考；
- 不用计算长度强制覆盖人工填写的渠段长度；
- 后续可增加“调查单元一般不超过3km”的提示，但V0.1先不作为硬性拦截。

---

## 17.3 附表2.2

- 孔数为整数且不得小于0；
- 宽、高、流量、保护层厚度、裂缝限宽不得小于0；
- 水闸类型适用性规则当前不自动判断。
