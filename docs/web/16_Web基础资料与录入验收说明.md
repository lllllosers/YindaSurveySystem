# Web 基础资料与调查录入验收说明

## 一、启动

双击仓库根目录的 `启动Web管理中心.bat`。控制台中“PostgreSQL”“业务后台”“网页服务”均显示“运行正常”后，点击“打开 Web 页面”。

本阶段验收地址：`http://127.0.0.1:8848`

如果控制台提示旧版后台占用 8000 端口，请关闭以前打开的后台命令窗口，再点击“启动全部服务”。启动器不会把旧版后台误认为当前可用版本。

## 二、建议验收顺序

### 1. 页面和用语

1. 登录后依次打开“单位与渠系”和“在线录入”。
2. 两个页面都应正常显示，不应出现英文 `Not Found`。
3. 可在地址栏输入一个不存在的页面地址，例如 `/does-not-exist`，系统应显示中文引导页，并可返回工作台。
4. 工作台“当前建议先做”应根据现有资料给出下一项业务动作；点击提示可以直接到达对应页面。
5. 各页面正文、表格、按钮和说明文字在 Windows 默认显示缩放下应清晰可读，不应依赖浏览器放大才能辨认。

### 2. 基础资料维护

为避免影响正式资料，建议新增一组带“验收测试”字样的临时资料：

1. 新增“验收测试管理处”。
2. 在该管理处下新增“验收测试一所”和“验收测试二所”。
3. 进入“渠系与分管”，新增“验收测试干渠”。
4. 在这条干渠所在行点击“管理分管所”，建立两个分管段：一所 `0+000—10+000`，二所 `10+000—20+000`。两个相邻区间应保存成功。
5. 再建立 `5+000—15+000`，系统应提示区间重叠并阻止保存。
6. 尝试直接停用测试干渠，系统应要求先处理仍在使用的分管范围。
7. 按“分管范围 → 渠道/管理所 → 管理处”的顺序停用，再删除临时资料。

骨干渠专项检查：在“渠系与分管”选择“待设置分管”，应看到尚未设置负责单位的干渠或分干渠。任取一条打开“管理分管所”，可选择“按桩号分段”；若正式边界暂未核实，也可先选择“边界待确认”，但不得凭空填写正式桩号。补充的分管关系会进入新任务快照，桌面端不需要再次维护一套。

渠系列表每页显示 10 条。切换“全部渠道”“干渠与分干渠”“待设置分管”或使用搜索后，应自动回到第一页，并正确显示当前范围和总条数。

检查要点：每次成功变更后，页面上的“中心正式版 R…”版本号应增加；有下级、任务或成果引用的资料只能停用，不能删除。

### 3. Web 在线录入闭环

1. 在“项目与批次”建立一个测试项目和进行中批次。
2. 在“调查任务”创建并下发一个水管所任务。
3. 打开“调查数据录入”，新建记录，选择任务、范围和调查表。
4. 填写必填资料和各项评价，先保存草稿，再提交审核。
5. 使用系统管理员或业务管理员账号执行“通过入库”。
6. 在“正式成果库”中按调查对象名称查询，应能找到该记录，来源应显示为 Web 在线录入。
7. 再新建相同项目、范围、调查表和对象名称的记录并提交，系统应提示正式库已有同名对象，阻止重复入库。

### 4. 桌面端联动

1. 从 Web“调查任务”下载 `.ydtask` 文件。
2. 在桌面端“任务接收”中导入，核对管理单位、渠道、分管范围和 14 张调查表。
3. 在桌面端完成一条现场调查并导出 `.ydresult`。
4. 回到 Web“成果接收与审核”上传，执行预检、审核和正式入库。
5. 在“正式成果库”查询该记录，来源应显示为桌面现场调查。

若 Web 已有同名同范围的待审核或正式记录，桌面成果预检应提示可能重复；反向操作时，Web 提交也应检查桌面已入库成果。

## 三、版本联动白箱检查

这项用于确认历史任务不会被后来修改：

1. 记录基础资料当前版本号并创建任务 A。
2. 修改一条与任务范围有关的基础资料说明，确认版本号增加。
3. 再创建任务 B。
4. 查看任务详情：任务 A 应保留旧版本，任务 B 应使用新版本。
5. 桌面端分别导入两个任务时，各自读取对应的冻结快照。

## 四、唯一事实源判断

- Web 草稿、桌面本地草稿都不是正式成果。
- 只有经过 Web 中心审核并进入 PostgreSQL 正式成果库的数据才是统一正式依据。
- 不要求 Web 记录复制到每台桌面电脑；桌面端只接收任务快照并回传成果。
- 正式记录需要修订时，应沿用原稳定编号和提高修订号，不能另建一条同名记录规避版本检查。

更完整的规则见 `docs/14_Web与桌面端数据协同规则.md`。
