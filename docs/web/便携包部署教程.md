# 引大调查 Web 中心 Windows 便携包部署教程

本包将 Web 后端、编译后的管理页面、正式成果原表 Excel 模板、Windows 服务控制台、Python 3.12 和 PostgreSQL 17 放在同一目录。目标电脑无需安装 Python、Node.js 或 PostgreSQL。包内不含账号、数据库、上传文件或密钥。

## 1. 部署前准备

- 使用 Windows 10/11 或 Windows Server 的 64 位系统，登录具有目标目录写入权限的账号。
- 准备一个固定且有足够空间的目录，例如 `C:\YindaWeb`。生产预检默认要求存储盘至少留有 5 GiB 空间；上传成果还需要额外容量。
- 确认本机 `8000`（Web）和 `55432`（便携 PostgreSQL）端口未被其他程序占用。
- 本机模式只监听 `127.0.0.1`，供部署电脑自己验收。需要给甲方提供外网地址时，先完成第 5 节的 HTTPS 配置。

将 `yinda-web-windows-portable.zip` **完整解压**到固定目录。不要在 ZIP 预览窗口里运行 EXE，也不要只复制 EXE。解压后的主要内容：

| 路径 | 作用 |
| --- | --- |
| `web_center\YindaWebServerConsole.exe` | 唯一的启动与维护入口 |
| `web_center\backend`、`web_center\frontend\dist` | Web API、数据库迁移、管理页面 |
| `templates\excel` | 正式原表导出模板 |
| `runtime\python`、`runtime\postgres` | 包内 Python 与 PostgreSQL |
| `DEPLOY.md` | 普通服务器部署与生产安全说明 |

首次解压后，`data`、`.env`、`storage` 和 `backups` 尚不存在；控制台初始化时才创建。若 Windows 提示缺少 Visual C++ 运行库，且包内存在 `runtime\vcredist_x64.exe`，先安装它再打开控制台。

## 2. 首次在本机启动

1. 双击 `web_center\YindaWebServerConsole.exe`。首次状态显示未配置或未连接是正常的。
2. 点击 **初始化便携环境**，填写管理员账号、显示名称与密码。初始化会生成随机数据库密码、创建本机 PostgreSQL 数据目录和业务库、升级数据库结构，并创建首位管理员。请保存管理员密码；控制台不会显示或保存该密码。
3. 初始化成功后点击 **启动 Web 服务**。控制台会启动包内数据库、执行本机运行环境预检，再启动隐藏的 Web 进程。看见“运行正常”后点击 **打开管理端**，或在这台电脑浏览器访问 `http://127.0.0.1:8000/`。
4. 使用刚创建的管理员登录。正式成果库可导出 CSV 汇总和附表 2.1～2.14 的正式 Excel 原表。

以后开机后，双击同一个 EXE，再点击 **启动 Web 服务**。关闭控制台窗口只会收起到系统托盘，Web 和数据库仍运行。需要彻底停服时点击 **停止全部**，再通过托盘菜单的“退出控制台”关闭 GUI。**停止 Web 服务**只停止 Web，数据库保持运行；**重启 Web 服务**不会清除数据。

“运行环境预检”在本机模式检查回环数据库、页面、迁移版本和数据目录可写性。若初始化或启动失败，请先查看控制台的“控制台操作”“环境预检”“Web 服务”日志，数据库启动日志位于 `logs\postgres.log`。不要重复解压覆盖来修复数据目录。

## 3. 数据、备份与日常维护

所有本机状态保留在解压目录中：

- `data\postgres`：PostgreSQL 数据库，**不能删除或单独覆盖**。
- `web_center\backend\.env`：本机数据库密码和部署配置，**不能提交 Git 或发送给他人**。
- `web_center\backend\storage`：上传的成果、附件与影像。
- `web_center\backend\backups`：控制台“立即备份”生成的数据库转储及同次 storage 快照。
- `web_center\.runtime`、`logs`：控制台进程状态与运行日志。

点击 **立即备份** 会使用包内 `pg_dump.exe` 创建 PostgreSQL 自定义格式备份，并复制 storage。备份前若数据库未启动，控制台会先启动它。备份完成后，把整个备份目录再复制到独立磁盘；不要只保留在同一台电脑上。升级、迁移或清空测试数据前必须先备份。

如需移动部署目录，先“停止全部”并退出控制台，再连同 `data`、`.env`、`storage`、`backups` 一起移动。数据库主版本为 17；不要用其他主版本的 PostgreSQL 二进制文件直接打开 `data\postgres`。不要同时从两个目录启动同一份数据库。

## 4. 用新便携包升级旧版本

1. 在旧目录的控制台点击 **立即备份**，将备份目录复制到另一块磁盘。
2. 点击 **停止全部**，确认 Web 和数据库已停止，再退出托盘中的控制台。
3. 把新 ZIP 解压到**同一个固定目录并覆盖程序文件**。保留原有 `data`、`web_center\backend\.env`、`web_center\backend\storage`、`web_center\backend\backups`、`web_center\.runtime`。不要先删除旧目录。
4. 双击新 `web_center\YindaWebServerConsole.exe`，点击 **启动 Web 服务**。若数据库结构尚未升级，可点击 **初始化便携环境**；已存在管理员时不会创建第二个管理员，该操作会运行数据库迁移。之后再启动 Web。
5. 检查管理端登录、`/api/v1/health`、正式成果库查询及 Excel 原表导出。确认无误后保留新备份。

若旧版是 `Start-Yinda.bat` 启动的 Web，先用旧包的 `Stop-Yinda.bat` 停止旧进程和数据库，再执行以上升级。新包不再提供 BAT/PowerShell 启动脚本；新控制台不会接管占用 `8000` 端口的陌生进程。

## 5. 提供 HTTPS 验收网址

本机模式使用 `APP_ENV=development` 和 HTTP，仅允许在部署电脑本机访问。给甲方外网验收前，需要配置可信的 HTTPS 隧道或反向代理，让其把唯一的公网 HTTPS 网站转发到**这台电脑的** `127.0.0.1:8000`。PostgreSQL `55432` 和原始 Web `8000` 不对公网开放。请先确认代理删除客户端自带的转发头，并按 `DEPLOY.md` 的部署边界配置网络。

1. 在控制台点击 **停止全部**。编辑 `web_center\backend\.env`，保留现有随机 `DB_PASSWORD` 和 `DB_PORT=55432`，设置：

   ```dotenv
   APP_ENV=production
   SESSION_COOKIE_SECURE=true
   ALLOWED_HOSTS=127.0.0.1,localhost,实际公网主机名
   REGISTRATION_MODE=invite_only
   PUBLIC_BASE_URL=https://实际公网主机名
   ```

   `ALLOWED_HOSTS` 只填主机名，不带 `https://`、路径或端口；`PUBLIC_BASE_URL` 填完整 HTTPS 根地址。把示例文字替换为真实主机名。保持数据库主机为 `127.0.0.1`。
2. 重新打开控制台，点击 **启动 Web 服务**。控制台会启动本机 PostgreSQL，并执行更严格的生产预检；有 `BLOCKER` 时不会启动 Web。按预检结果修正 `.env`、HTTPS Host、数据库或目录权限后重试。
3. 使用控制台 **打开管理端** 进入已配置的 HTTPS 地址；生产模式使用安全 Cookie，**不要使用本机 HTTP 地址登录**。检查 HTTPS 登录、健康检查和 Excel 原表导出。

便携数据库不是 Windows Service。每次电脑重启后仍需打开控制台并点击“启动 Web 服务”。本包不设置开机自启；如需无人值守运行，请按 `DEPLOY.md` 将 PostgreSQL 部署为系统服务，并另行规划 Web 自启和备份。

## 6. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| EXE 提示 Qt DLL 错误 | 使用本包内的新版 EXE；不要与旧 EXE 或旧 Qt DLL 混放。完整解压后重试。 |
| 初始化失败 | 确认目录可写、`55432` 未被占用、磁盘空间足够；查看 `logs\postgres.log` 和控制台操作日志。若已有 `data\postgres` 但 `.env` 丢失，先从备份恢复 `.env`，不要重新初始化。 |
| 启动显示 8000 被占用 | 先确认是否为旧版 Web 进程，并使用旧版停止方式退出；控制台不会强制接管或结束不属于本包的进程。 |
| 管理页面无法打开 | 确认控制台 Web 卡片为“运行正常”，本机检查 `http://127.0.0.1:8000/api/v1/health`，再查看 Web 服务日志。 |
| 生产模式不能登录 | 通过配置的 HTTPS 地址访问；核对 `SESSION_COOKIE_SECURE=true`、HTTPS 代理和 `ALLOWED_HOSTS`。 |
| 备份失败 | 确认 `runtime\postgres\bin\pg_dump.exe` 存在、备份盘可写且有足够空间，查看控制台备份日志。 |

需要恢复数据库和 storage 时，应停止全部服务，并使用**同一次备份**中的数据库转储与 storage 快照；不要只恢复其中一项。恢复前再复制一份当前目录并请熟悉 PostgreSQL 的管理员操作，避免覆盖仍有价值的数据。
