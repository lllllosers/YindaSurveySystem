# V1.1.1 发布说明

## 版本信息

- 产品名称：引大入秦工程现状调查采集系统
- 版本：V1.1.1
- 阶段：正式版
- 发布日期：2026-09-21
- 升级基线：V1.1.0

## 版本定位

V1.1.1 是 V1.1.0 的维护修正版。

本版本不改变数据库模型、任务包/成果包协议和既有三级任务架构，重点修复甲方在 V1.1.0 正式测试中发现的处级任务接收后界面问题，并统一收口用户可见文案。

## 本次修复

### 1. 处级任务接收后“任务分发”白屏

V1.1.0 在处级父任务工作区进入任务分发页面时，部分组织机构查询结果仍以 `sqlite3.Row` 进入后续映射读取逻辑，导致页面初始化异常。

V1.1.1 已统一在 UI 业务逻辑入口转换为普通字典，处级父任务接收后可以正常进入任务分发页面并选择下属水管所。

### 2. 处级任务接收后调查录入无法选择水管所和渠系

V1.1.0 的通用调查录入页仍把任务目标机构统一按“水管所”解释。处级父任务中的目标机构实际是基层处，因此会错误过滤全部水管所。

V1.1.1 已按任务目标类型区分：

- 所级任务继续只允许当前任务目标水管所；
- 处级父任务允许选择父任务冻结范围实际涉及的下属水管所；
- 切换水管所时，只显示该水管所在父任务冻结范围内的渠道与分管范围；
- 不允许跨水管所串用其他所的冻结范围。

该修复不放宽任务授权边界，仍以父任务冻结范围为上限。

### 3. 成果接收提示用户化

成果包检查与导入界面不再直接向业务人员展示：

- 内部错误代码；
- UID；
- `package_uid` / `result_uid`；
- `revision`；
- `Registry`；
- “数据库事务”“工作区”“托管”等开发实现术语。

界面改为直接说明：

- 当前是否可以继续；
- 是否存在必须处理的问题；
- 是否只是说明性信息；
- 用户下一步应做什么。

内部技术代码和 UID 仍保留在服务层对象与自动化测试中，便于开发诊断，不改变数据协议。

### 4. 历史分管范围提示级别修正

当当前基础资料中的分管范围已经变化或不存在，但成果仍能通过原任务下发时保存的冻结范围完整核验时：

- 不再显示为需要用户处理的“警告”；
- 改为“说明”；
- 明确告知“已按任务下发时保存的范围完成核验，不影响本次历史成果导入”。

若任务来源或冻结范围本身无法核验，原有阻止或警告逻辑继续保留。

### 5. 全页面文案巡检

V1.1.1 对桌面端全部主页面和公共业务组件执行一次用户视角文案巡检，覆盖：

- 首页；
- 项目/批次；
- 组织机构；
- 渠道与分管范围；
- 调查录入；
- 工程台账；
- 数据查询；
- 任务分发；
- 任务接收；
- 成果提交；
- 成果接收；
- 工程详情；
- 影像管理。

同时增加用户可见文案回归测试，防止后续开发重新把内部技术术语直接带回业务界面。

## 未改变的内容

V1.1.1 不改变以下 V1.1.0 正式能力：

- 中心 → 基层处 → 水管所 → 基层处 → 中心三级任务与成果链；
- `task_uid / parent_task_uid / root_task_uid / task_depth` 任务谱系；
- `source_task_uid + source_management_scope_uid` 调查来源；
- `submission_task_uid` 分级成果提交授权；
- 父任务冻结范围与子任务范围约束；
- `.ydtask` V3 / `.ydresult` 2.2 数据交换协议；
- EngineeringAsset / SurveyRecord 稳定 UID；
- revision 增量合并、旧版本与冲突保护；
- 工程业务编号重复整理与正式锁号；
- 附表2.1～2.14正式调查能力；
- V1.0.0～V1.1.0 历史 Tag 和 Release。

## 升级说明

V1.1.1 可直接替换 V1.1.0 程序使用。

本版本没有新增数据库迁移要求，也没有改变 `.ydtask` / `.ydresult` 文件协议。已有 V1.1.0 `local_data` 可继续使用。

正式升级前仍建议备份 `local_data`。
