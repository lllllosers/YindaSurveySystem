## 三级任务与成果模型

### 中心 → 处

中心可选择基层处作为任务目标。处级父任务冻结的是选中水管所 scope 的集合，不创建虚构的“处级 CanalManagementScope”。

### 处 → 所

基层处只能从当前父任务冻结范围中派生子任务：

```text
child scopes ⊆ parent frozen scopes
```

目标水管所必须是当前处的直接下属，且每个子任务 scope owner 必须与目标水管所一致。

### 所 → 处

所级成果按本地 issued child task 回传，调查记录保留：

```text
source_task_uid
+
source_management_scope_uid
```

处端按自己实际下发的子任务冻结历史预检和导入。

### 处 → 中心

处端从当前父任务范围内自动汇总合法 completed 记录，并生成：

```text
submission_task_uid = 父任务 T1
```

每条记录的 `source_task_uid` 继续保留 T2/T3 等真实采集来源。

中心按自己实际下发的 T1 验收处级汇总，并再次校验记录 scope 是否属于 T1 冻结授权范围。

## 工程编号与增量成果

V1.0.2 建立的以下原则继续保持：

- 稳定 UID 是跨数据库身份；
- `business_code` 只是可重排业务编号；
- 编号变化不增加业务 revision；
- 同一具体渠道按工程类型和桩号顺序重复整理编号；
- 正式锁号前执行连续性和完整性预检；
- 同 UID 成果按 revision / 内容区分一致、更新、旧版本和冲突；
- 接收端保留自己的编号事实，不被下级暂编编号覆盖。

## 当前架构原则

- EngineeringFormRegistry 是附表2统一身份入口；
- `CanalUnit` 只表达物理渠道，`CanalManagementScope` 表达管理责任；
- 历史任务按冻结快照验收，不由 current master 反向改写；
- 任务 lineage 与调查 record provenance 分离；
- `source_task_uid` 永远表示真实调查来源任务；
- `submission_task_uid` 只表示当前成果提交所依据的上级任务；
- 不通过伪造 issued history 实现三级链；
- completed 记录可继续修改，但必须保持完整；
- 稳定 UID 不随业务编号或汇总层级变化；
- Web Hybrid / Web Center 保持独立实验方向，不混入桌面稳定主线。
