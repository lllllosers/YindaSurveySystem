# 桌面端存量数据接续与双端协同方案

## 一、基本原则

甲方已经正式使用桌面端，既有项目、批次、任务和成果不重新建立，也不修改原有稳定 UID。

系统只保留一套正式事实：

```text
桌面端 SQLite = 离线工作区和历史原始资料
任务包 .ydtask = 调查授权和冻结范围
成果包 .ydresult = 调查成果及照片、视频的受控交换文件
Web 正式成果库 = 审核通过后的唯一查询、汇总和管理入口
```

Web 不直接连接正在使用的桌面端 SQLite，避免多人同时操作造成数据库损坏，也避免形成无法追溯的“后台自动同步”。

## 二、已有数据如何接续

### 1. 先登记已经下发的任务

在 Web“任务下发”页面点击“接续已有桌面任务”，可以一次选择多个原始 `.ydtask` 文件。

系统会：

- 使用桌面端正式读取器检查文件完整性；
- 保留原项目、批次、任务、父子任务、分管范围和调查表 UID；
- 自动补建 Web 中尚不存在的项目和批次；
- 保存任务下发时冻结的单位、渠系和分管范围；
- 相同任务重复登记时自动识别，不重复生成数据；
- 同一任务 UID 对应不同文件时停止接续，要求人工核对。

登记完成后，原桌面任务仍然继续使用，不需要重新向基层发包。

### 1.1 原始任务文件不齐时

系统管理员可以在 Web“调查任务中心”点击“从桌面中心库接续”，选择桌面端中心数据库的完整备份（`.db`、`.sqlite` 或 `.sqlite3`）。

此通道只读取桌面端已经正式下发的不可变任务历史：

- 数据库备份始终以只读方式打开，不执行桌面端迁移，不修改源文件；
- 只接续正式下发任务、任务谱系和下发时冻结的分管范围，不导入未下发草稿；
- 保留原任务 UID、原任务文件 UID、项目批次 UID 和父子任务关系；
- 原任务文件缺失时，根据下发历史重建一份可由当前桌面端检查和接收的兼容任务文件；
- Web 中已经存在的同一任务自动跳过，身份冲突的任务单独列出，不覆盖已有数据；
- 缺失的项目和批次按历史快照补建，当前基础资料不会反向改写历史任务范围。

为避免正在写入的 SQLite 文件和 WAL 文件没有一并备份，推荐先退出桌面端，再复制中心数据库；如桌面端提供备份功能，应优先使用其生成的完整备份。原始 `.ydtask` 仍是首选接续材料，数据库备份是文件不齐时的兜底通道。

### 2. 再回收已有和后续成果

在原桌面端按现有方式生成 `.ydresult` 成果包，在 Web“成果审核”中可以一次选择多份成果文件。

成果包包含：

- 工程对象；
- 调查记录；
- 分项评价；
- 原始任务来源和本次提交任务；
- 照片、视频及其哈希、部位、用途和备注。

Web 按已经登记的原任务冻结范围进行核验。审核通过并正式入库后，成果进入中央成果库，原 UID、版本号和来源任务均保持不变。

### 3. 大量历史成果的推荐顺序

1. 先备份原桌面端 `local_data`；
2. 按“项目/批次”整理原始任务包，并保留中心数据库完整备份；
3. 在 Web 批量登记原始任务包；缺少的任务再从中心数据库备份接续；
4. 在桌面端按任务或批次分批生成成果包；
5. 在 Web 批量上传成果包；
6. 先做文件检查和业务核验，再分批审核入库；
7. 对比桌面端与 Web 的工程数、记录数和影像数；
8. 核对无误后，新任务统一改由 Web 下发。

不建议一次把所有成果直接审核入库。按批次分批处理，可以在发现历史资料问题时准确定位和回退。

## 三、新业务的双端协同

### Web 新任务

```text
Web 建立项目/批次并下发任务
        ↓
下载 .ydtask 交给管理处或水管所
        ↓
桌面端接收任务并现场离线调查
        ↓
桌面端生成 .ydresult
        ↓
Web 文件检查 → 业务核验 → 审核 → 正式入库
```

### Web 在线补录

Web 在线记录必须选择一个已登记任务和该任务冻结的分管范围。在线补录与桌面离线录入共用同一套项目、批次、任务和正式成果库。

在线记录支持草稿、照片/视频上传、提交、退回修改和审核入库。影像在审核入库前属于草稿附件，审核后与调查记录一起进入正式成果库。

## 四、重复和冲突处理

- 工程对象、调查记录、任务、影像都以稳定 UID 识别，不以文件名识别；
- 相同成果包重复上传只返回既有提交，不重复写入；
- 同 UID、同版本、同内容视为已存在；
- 同 UID、较高版本按更新处理；
- 同 UID、同版本但内容不同视为冲突，禁止自动覆盖；
- 不同 UID 但项目、单位、渠道、工程类型和名称相同，提示可能重复并停止入库；
- Web 在线待审核记录与桌面成果发生同名冲突时，要求审核人员确认保留哪一条；
- 正式成果不会被当前基础资料反向改写，始终保留调查发生时的历史任务范围。

## 五、照片和视频

照片、视频不直接存进数据库二进制字段：

- 桌面端影像保存在 `.ydresult` 归档中，Web 保存文件哈希和归档位置；
- Web 在线影像保存在服务器受控目录，数据库保存元数据和哈希；
- 正式成果详情可以直接查看或下载两种来源的影像；
- 删除草稿影像会同时删除服务器文件；记录提交后禁止随意删除；
- 成果入库时再次核对影像记录和文件大小，防止归档错位。

## 六、正式切换建议

在存量接续验收完成前，原桌面端中心库保持只读备份，不删除、不覆盖。新任务切换到 Web 下发后，原桌面端仍作为现场离线客户端使用，不再作为第二套中心总库。

正式切换完成的判断标准：

- 尚在执行的原桌面任务已全部在 Web 登记；
- 选定历史批次的工程、调查记录、评价和影像数量核对一致；
- 新任务能够从 Web 下发并由桌面端正常接收；
- 桌面成果能够回传 Web 并通过任务范围核验；
- Web 在线补录能够与桌面成果统一查重；
- 正式成果详情能够查看两种来源的照片和视频；
- 相同任务包、成果包重复操作不会产生重复数据。
